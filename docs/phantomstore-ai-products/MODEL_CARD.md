# Analysis System Card: Local Deterministic Domain Engines v2

## System

Ten schema-validated analytical engines implement a complete Milestone 2 core loop per product. Active path: `deterministic-domain-v1`. Compatible conservative path: `deterministic-conservative-v1`. Both satisfy the same output schema. No external model is activated.

## Output contract

Every run records task ID, provider path, source-field digest, creation time, zero token/cost metadata, review requirement, summary, metrics, value/unit/formula/inputs/rounding, table, source-linked claims, warnings, and method. Outputs are stored separately from the versioned human source artifact.

## Intended use

- Compare declared planning scenarios and options.
- Structure dates and expose chronology gaps.
- Compile controlled benchmark recipes.
- Inspect simple process capacity.
- Compare declared negotiation packages without covert inference.
- Measure explicit architecture traceability.
- Rank user-supplied site scores and expose source age.
- Balance declared evidence quality without issuing a truth verdict.
- Validate explicit dependency identifiers and source coverage.
- Inspect an unadjusted difference in proportions and uncertainty interval.

## Prohibited use

Autonomous consequential decisions; liability or guilt judgments; surveillance; biometric identification; safeguard evasion; unauthorized training; employee decisions; coercion/deception; silent deployment; military targeting; individual tracking; fabricated citations; source-system edits; causal claims without design support; medical trial guidance.

## Evaluation

Golden fixtures verify ten different formulas and product-specific core-loop outcomes. Contract tests verify provider truth, zero cost, evidence links, formula metadata, fallback compatibility, output schema, durable job transitions and retry, human review, source preservation, staleness after edits or consent withdrawal, source dependency handling, entitlement and kill-switch enforcement, deletion recovery, privacy-safe traces, and tenant isolation.

## Limitations

The system performs transparent calculations and structured parsing, not general language-model reasoning. User inputs may be wrong, biased, stale, incomplete, or strategically misrepresented. Chronicle accepts text rows rather than multimodal files; Terrain does not fetch maps; Foundry plans fixture recipes but does not generate model-written samples; Causal does not establish identification. Metrics are method outputs, not calibrated confidence. Independent domain and model-risk review remains required.

## Human oversight

All analyses start `pending_review` and must be accepted, corrected, or rejected. Corrections are retained as evaluation feedback but are not used for automatic training. The source revision is unchanged by review.
